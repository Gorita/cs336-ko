# cs336-note: 학습 노트 작성 스킬

## 핵심 원칙

> **AI는 사용자가 못 던지는 질문을 던지고, 사용자의 답변을 정돈된 문장으로 조립한다. 그 이상은 안 한다.**

이 스킬의 유일한 가치:
1. 입력의 **자족성** (미래의 자신이 읽을 수 있는가) 평가
2. 부족하면 **하나씩** 질문해 사용자가 채우게 함
3. 사용자 답변을 **사용자 어휘 보존** 한 채로 정돈된 문장으로 조립
4. 사용자 확인 후 저장

## 호출 형태

```
/cs336-note <입력>
/cs336-note --raw <입력>    # 평가/조립 skip, 그대로 저장
```

## 실행 단계

### 1. 컨텍스트 추론 (자동, 사용자에 묻지 않음)

다음을 자동으로 파악:
- 현재 강의: cwd, 최근 읽은 파일, 최근 대화 토픽으로 추론
  - 예: `workspace/spring2025-lectures/lecture_01.py` 를 최근 봤으면 → Lec 1
  - 예: `lectures/lec01-tokenization/` 폴더에서 작업 중 → Lec 1
  - 추론 불가능하면 사용자에게 물음 ("어느 강의 노트?")
- 노트 파일 경로: `workspace/notes/lec{NN}.md`
- 오늘 날짜

### 2. 자족성 평가

다음을 체크:

| 항목 | 체크 포인트 |
|------|-----------|
| 주어/대상 | "이게", "그것" 등 지시어가 외부 컨텍스트 없이 이해되나? |
| 요점/insight | 단순 키워드("BPE 흥미로움")로 그치지 않고 무엇이 왜 중요한지 표현됐나? |
| 비교 대상 | "더 빠름", "더 효율적" — 무엇과 비교했는지 명시? |
| 시간 의존 | "아까 본 것" — 무엇 얘기인지 풀려 있나? |
| 약어/단축 | 사용자만 아는 줄임말 풀려 있나? |

**충분 기준** (보수적):
- 입력이 ≥ 50자이고 위 체크리스트가 모두 OK → 자족적 (질문 안 함)
- 명백히 단편 / 키워드 / 지시어 포함 → 부족 (질문 필요)
- 애매하면 → 자족적 쪽으로 (사용자 짜증 방지)

### 3. 반복 구체화 (부족할 때만)

```
loop:
  부족한 점 중 가장 critical 한 것 1개 선택
  → 사용자 단어를 인용한 구체적 질문 (일반 "왜?" 금지)
  → 사용자 답변 받기
  → 다시 자족성 평가
  → 충분하면 break
soft limit: 3회 (그 이상 가지 않음)
```

**질문 예시**:
- "이게 가 BPE의 통계 기반인 점을 가리키는 거야? 아니면 다른 부분?"
- "어떤 점에서 흥미로워?"
- "어떤 것보다 더 빠르다는 거야?"
- "GPT-4 1조 — 파라미터? 토큰? 어떤 거?"

**일반 질문 금지**:
- ❌ "왜?"
- ❌ "더 자세히 말해줘"
- ❌ "정확히 뭐야?"
- ✅ 사용자가 쓴 단어를 인용한 구체적 질문

### 4. 정돈 (Polishing)

원본 입력 + 사용자 답변들 → 한 문장(들) 으로 조립.

**해도 되는 것**:
- ✅ 단편들을 문장으로 연결
- ✅ 문법적으로 완전하게
- ✅ 사용자가 명시적으로 답한 referent 보강 ("이게" → "BPE의 통계 기반인 점")

**절대 안 하는 것**:
- ❌ 사용자가 안 한 해석 추가 ("이는 결국 ... 와 연결됨")
- ❌ 학술 용어로 다시 쓰기 (사용자가 "신기"라고 했으면 "신기")
- ❌ 의미 보강 / 추론 / 일반화

### 5. 사용자 확인

```
정돈하면 이렇게 되는데 OK?
> {정돈된 노트}

응답:
- "응" / "OK" / "저장" → 그대로 저장
- "이렇게 바꿔: X" → 사용자 수정본 저장
- "아니, 다시" → 처음부터 다시
```

### 6. 저장

`workspace/notes/lec{NN}.md` 에 다음 형식으로 추가:

#### 파일 형식

```markdown
# Lecture 1 — Tokenization

## 2026-05-07
- BPE의 통계 기반인 점이 흥미로움 — 학습 데이터에 따라 토크나이저 자체가 달라진다.
- [ ] vocab 크기를 키우면 trade-off가 뭐?
- [x] BPE merge 우선순위? → 빈도 높은 쌍 우선.

## 2026-05-08
- ...
```

**형식 규칙**:
- 파일 첫 줄: `# Lecture {N} — {Topic}`
- 일자별 `## YYYY-MM-DD` 헤더 (없으면 추가)
- 모든 항목 bullet (`-`)
- 질문 (입력에 `?` 있거나 의문문) → `- [ ] ` 으로 시작
- 분 단위 timestamp 안 씀 (불필요한 노이즈)

#### 저장 후 알림

한 줄로 간결하게:
```
✓ 저장됨 (workspace/notes/lec01.md)
```

추가 정보가 있으면 한 줄 더 (옵션):
- 오늘 N번째 노트
- 미해결 [ ] 누적 개수

## 보조 동작

### 학습 시작 시 (별도 명령 또는 첫 호출)

```
/cs336-note --start
```

→ `workspace/notes/lec{NN}.md` 의 미해결 `[ ]` 항목 표시:
```
지난번 미해결:
- vocab 크기를 키우면 trade-off가 뭐? (2026-05-07)
- ...
```

### 학습 종료 시

```
/cs336-note --end
```

→ 오늘 작성한 노트 / 남은 미해결 요약:
```
오늘 노트: 5개
미해결: 2개
- vocab 크기 trade-off?
- ...
```

## --raw 플래그

평가 / 조립 / 확인 모두 skip. 입력 그대로 저장.

```
/cs336-note --raw 빠르게 적는 것
```

→ 형식 처리만 (timestamp, bullet, 파일 경로) 후 저장.

## 안티패턴 (절대 하지 말 것)

1. ❌ AI가 사용자 답변을 해석/요약해서 다른 말로 저장
2. ❌ "왜?" 같은 일반 질문 (반드시 사용자 단어 인용)
3. ❌ 자족적인 입력에 굳이 질문하기
4. ❌ 한 호출에 질문 여러 개 한 번에 (한 번에 하나씩)
5. ❌ AI가 자기 추측으로 "이건 X 맞지?" 라고 강하게 단정 (확신 없으면 열린 질문)
6. ❌ 사용자가 노트에 안 쓴 메타 인사이트를 자동 추가

## 디자인 결정 기록 (변경 시 참고)

- **Timeline 기반** (concept 기반 아님) — 작성 부담 최소화
- **분 단위 timestamp 제거** — 6개월 후 의미 없음
- **`[ ]` / `[x]` 사용자 직접 판단** — AI가 자동 마킹 X
- **카테고리 분류 안 함** — 정리 자체는 학습에 0 기여
- **객관 메타데이터만 자동** — 시간, 강의 (해석 / 추론 X)
- **호출당 질문 1개** — 짜증 방지
- **soft limit 3회** — 무한 루프 방지

## 사용 예시

### 예시 1: 짧은 입력 → 반복 구체화

```
사용자: /cs336-note 이게 흥미로움
AI: '이게'가 뭐야? 방금 BPE 얘기 중이었는데, BPE 관련?
사용자: BPE의 통계 기반인 점
AI: 어떤 점에서 흥미로워?
사용자: 학습 데이터에 따라 토크나이저 자체가 달라지는 점
AI: 정돈하면 이렇게 되는데 OK?
    > BPE의 통계 기반인 점이 흥미로움 — 학습 데이터에 따라 토크나이저 자체가 달라진다.
사용자: 응
AI: ✓ 저장됨 (workspace/notes/lec01.md)
```

### 예시 2: 충분히 자족적 → 즉시 저장

```
사용자: /cs336-note BPE는 통계 기반 휴리스틱이라 학습 데이터에 따라 토크나이저 자체가 달라진다는 점이 흥미로움

AI: 자족적이라고 판단. 이대로 저장할까?
    > BPE는 통계 기반 휴리스틱이라 학습 데이터에 따라 토크나이저 자체가 달라진다는 점이 흥미로움.
사용자: 응
AI: ✓ 저장됨
```

### 예시 3: 질문 입력

```
사용자: /cs336-note vocab 크기 키우면 어떻게 돼?
AI: 자족적인 질문으로 판단. 미해결로 저장할까?
사용자: 응
AI: ✓ 저장됨 ([ ] 미해결 마킹)
```

### 예시 4: --raw 플래그

```
사용자: /cs336-note --raw 너무 빨리 가는 듯
AI: ✓ 저장됨 (raw, 평가 skip)
```
